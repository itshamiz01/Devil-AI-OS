## 1. Executive summary

The Dynamic Agent Factory is implemented on top of P-01/P-02/P-03 with
maximal reuse: the P-01 `agents` registry, permission engine,
hash-bound approvals, audit trail, task engine and monitor, and the
P-02 shared model router were all extended, not duplicated. 9 genuinely
new tables, one additive migration (`a694abea811f`), 44 new API
endpoints, 7 new event types, 58 new tests. Full suite: **230 passed
in one run** (172 regression + 58 new). Real-uvicorn smoke demonstrates
Scenarios A, B, C, D, H, I live. No LLM is used by any factory
decision; no real LLM exists in this sandbox and none was simulated as
real.

## 9. Dynamic creation workflow

Deterministic 9-gate pipeline (factory stop → capability validity →
delegation limits → failed-init cap → **reuse first** → template
resolution → approval determination → fleet limits → resource
pressure) producing the six §7.3 decisions as persisted records;
hash-bound owner approvals with drift detection; idempotency keys;
initialization checks with a FAILED terminal state instead of retry
loops. Detail: `docs/architecture/P04_DYNAMIC_AGENT_FACTORY.md`.

## 10. Permission and approval architecture

Capability catalogue with §8.3 levels 0–3; Level 3 prohibited
structurally (no approval path); grants in a factory ledger mirrored
into the P-01 permission engine (deny wins); Level-2 grants and
restricted creations via hash-bound P-01 approvals decidable only by
the owner. Detail: `docs/architecture/AGENT_PERMISSION_MODEL.md`.

## 11. Resource management behavior

Per-agent budgets clamped by factory ceilings; host/queue pressure
levels 0–2 driving the §10.4 ladder; ladder blocking honours the P-01
`block_nonessential_on_threshold` switch while pressure is always
reported; shared-inference gate at 1 concurrent selection (CPU-only
hardware); idle suspension and degraded reconciliation in maintenance.
Detail: `docs/architecture/AGENT_RESOURCE_MANAGEMENT.md`.

## 12. Lifecycle implementation

§11 graph with validated transitions, the documented `created` legacy
bridge, busy-agent config lock, and history-preserving retirement.
Detail: `docs/architecture/AGENT_LIFECYCLE.md`.

## 13. Monitoring and metrics

Deterministic health states (HEALTHY/WARNING/DEGRADED/FAILED/
UNRESPONSIVE/UNKNOWN) computed from measured assignment outcomes;
metrics API with mandatory measured/estimated/unavailable labels —
accuracy/token/per-agent-memory/human-acceptance are reported
**unavailable**, never invented.

## 14. Security controls

is deterministic backend logic; audit has no delete surface. Detail:

## 17. Known limitations

- No real LLM exercised (none exists in the sandbox); the factory is
  fully deterministic and the LLM path is only the P-02 router's
  baseline-vs-profile selection, verified via the router itself.
- 9 capabilities are catalogued but unsupported (no backing module
  exists yet) and can never be granted: memory_write (P-09),
  file_read/write, api_read/write, code_generation,
  sandboxed_code_execution, browser_interaction,
  external_communication (P-05/P-06).
- `financial_transaction_request` records requests only; no money
  movement exists anywhere in the system.
- No frontend exists in staging; factory data is API-only until P-11
  (Command Center), per the prompt's own condition.
- Grant ledger → permission-engine mirror is a single call chain, not
  transactional across both stores; the ledger is authoritative.
- Task cancellation is cooperative (P-01); emergency stop cancels
  eligible queued tasks immediately.
- Pressure *blocking* follows the P-01 admission switch (off in the
  test harness); with production defaults it is on.

## 18. Deferred functionality

Memory engine (P-09 — only the §15 scoped interface exists);
execution/browser capabilities (P-05/P-06, §28 boundary respected);
frontend (P-11); real-model verification on the owner's hardware
(P-00 environment item).

## 19. Remaining technical risks

- First real Ollama model on CPU-only hardware may be slow; factory
  defaults already assume 1 inference slot and background-tier models.
- SQLite write contention if the fleet grows; ceilings (12 total /
  8 active) keep this bounded by design.
- Windows behaviour unverified until the owner's machine evidence
  lands (carried since P-00).
