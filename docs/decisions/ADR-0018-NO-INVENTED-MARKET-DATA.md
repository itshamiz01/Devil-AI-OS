# ADR-0018: No invented market data — an empty source catalog and a deny-all egress allowlist

- **Decision ID:** ADR-0018
- **Status:** Implemented for P-03
- **Context:** P-03 must produce business opportunities backed by real market evidence. The build environment permits outbound connections to exactly six hosts — `github.com`, `codeload.github.com`, `api.github.com`, `registry.npmjs.org`, `pypi.org`, `files.pythonhosted.org`. None is a market source. A probe at the HTTP level found **2 of 16 research URLs usable** and neither of those a search engine, marketplace, forum, trend service, government statistics site or vendor pricing page. An earlier TCP-connect probe reported 28 of 29 hosts "reachable", which was false: a transparent proxy completes the handshake and then drops the TLS negotiation. The full evidence is at [`docs/reports/P03_SOURCE_ACCESS_PROBE.txt`](../reports/P03_SOURCE_ACCESS_PROBE.txt).
- **Problem:** A phase whose entire output is supposed to rest on observed market data cannot observe any. Two dishonest options present themselves naturally. The first is to seed the catalog with plausible-looking sources and let the adapters fail at runtime, which produces a system that *appears* configured and reports refusals as though they were an operational fault rather than a design fact. The second is to mock the sources so the pipeline always has something to analyse, which yields green tests and a report full of numbers that describe no market at all.
- **Options considered:** (a) ship a populated `default_source_catalog()` of realistic sources; (b) mock adapters in the production path so acquisition always succeeds; (c) synthesise plausible evidence when none is obtainable, to exercise the downstream analytics; (d) ship an empty catalog with a deny-all allowlist, build the real acquisition layer, and make every absence explicit in the output; (e) defer the phase until a network is available.
- **Selected decision:** (d). `default_source_catalog()` returns `()`. `research_permitted_hosts` defaults to `""`, which `Settings.research_host_allowlist` renders as an empty tuple, and `NetworkPolicy.permitted_hosts` defaults to `frozenset()` with `allow_any_https=False` — deny all. The acquisition layer is fully implemented: `HttpSourceAdapter` performs real HTTP through an injectable transport, `NetworkPolicy.host_permitted` is a real gate, and all twelve `RefusalCategory` values are reachable. What is absent is permission to use it, not the code.
- **Reasons:** (a) would misrepresent the system's state and make a `host_not_permitted` refusal look like a bug to fix rather than a policy to change. (b) is the same error ADR-0017 rejected for models: a mock in a production path is indistinguishable from the real thing to the code around it, so the system learns to trust fabricated output. (c) is worse still — synthesised evidence would flow into market sizing, pricing, scoring and a report, and every one of those numbers would be a fiction wearing the clothing of an observation. (e) abandons a phase that can be built and verified honestly. (d) makes the constraint visible in configuration the owner controls, and makes the pipeline's response to absence — named refusals, `insufficient_data`, `INSUFFICIENT_EVIDENCE`, nine sections each stating what could not be determined — the thing that is actually tested.
- **Consequences:**
  - With no sources registered, every acquisition attempt produces a refusal. `fetch_many` returns a per-source `FetchResult` so one bad source cannot abort a batch, and a single `fetch` of an unknown id raises `SourceNotFoundError` because that is a programming error rather than a research outcome.
  - **A refusal is a finding, not an error.** Refusals are summarised into the report's evidence section, `WorkflowReport.total_refusals` is reported alongside `total_evidence` on every run, and a research sweep that reaches no source **completes** rather than fails — failing would make the P-01 task manager retry an outcome that is already correct. See ADR-0021.
  - Zero admissible evidence produces a definite, tested result rather than a crash or a guess: `INSUFFICIENT_EVIDENCE`, `recommendable=False`, `attractiveness == 0`, `scorable_count == 0`, TAM/SAM/SOM `None`, validation level 0, market verdict `insufficient_data`, saturation `unknown`, no business model invented, and a hard rejection naming coverage.
  - `MarketSizing` leaves a market `None` rather than zero when it cannot be sized, because zero is a claim that the market is empty and `None` is a claim that it was not measured. Likewise saturation distinguishes `empty` (looked, found nobody) from `unknown` (never looked).
  - All nine report sections always render. A section with no assessment object falls back to `NO_EVIDENCE_STATEMENT`; a section whose assessment exists renders that assessment's own honest verdict.
  - `is_test_data` defaults to **`True`** and `TEST_DATA_NOTICE` states in terms that the report is synthetic and not real market research. Claiming otherwise requires an explicit `is_test_data=False`, which nothing in this phase can legitimately supply.
  - `EvidenceExtractor` caps every extracted record at classification `supporting`, prefixes fixture claims with `"TEST FIXTURE "`, and **skips malformed prices rather than guessing** — a wrong price silently poisons every downstream projection.
  - Registering a source succeeds and is useful, but the API response states that registration does **not** place the host on the allowlist. "What is this source" and "may we contact it" are two separate owner decisions.
  - **No market statistic, price, review count, market size, vendor name, URL or date anywhere in the P-03 code, tests, fixtures or documentation is presented as observed.** The sample report at [`docs/reports/P03_SAMPLE_OPPORTUNITY_REPORT.md`](../reports/P03_SAMPLE_OPPORTUNITY_REPORT.md) is generated from mock fixtures and labelled accordingly.
  - The owner can change this without a code change: set `research_permitted_hosts` and register sources. The allowlist is the only gate, and widening it is an explicit act.
