# ADR-0021: The research task handler reaches the engine through an explicit binding, and a no-source sweep completes rather than fails

- **Decision ID:** ADR-0021
- **Status:** Implemented for P-03
- **Context:** §24 requires research sweeps to run through the P-01 task layer so that they are queued, approved, retried, cancelled and audited like any other unit of work. `ResearchTaskSpec.handler()` returns `"research.sweep"` for all six research stages (`source_sweep`, `market_sizing`, `competitor_scan`, `cost_verification`, `demand_verification`, `compliance_scan`), with the stage carried in the payload. The P-01 handler contract is `async execute(payload, ctx)` where `ctx` is an `ExecutionContext(task_id, cancellation)` — **handlers receive no services**. The opportunity engine lives in `OpportunityServices`, built by `factory.build_opportunities` during application startup.
- **Problem:** A handler that needs the engine but is not given it has three bad options: reach into module-level application state implicitly, construct its own engine (duplicating registries, evidence stores and repositories so the task's work is invisible to the API), or import the composition root (creating a cycle, since the composition root imports the task manager which imports the handlers). Separately, in this environment every sweep reaches no source at all, because the allowlist is deny-all per ADR-0018. If that outcome is reported as a task *failure*, the task manager will retry it — repeatedly, forever, correctly each time.
- **Options considered:** (a) an implicit global holding the current application; (b) handlers constructing their own engine from `Settings`; (c) an explicit `set_research_backend(services)` binding installed at startup and cleared at shutdown, raising loudly when unbound; (d) extending the handler contract to pass services through `ExecutionContext`.
- **Selected decision:** (c) for the binding, plus: a sweep that reaches no source **completes**. (d) was rejected as it changes a P-01 contract that four handlers and the whole approval gate already depend on; (a) and (b) are rejected below.
- **Reasons:** (a) makes the dependency invisible — a handler works in one process layout and silently does something else in another, and tests cannot tell which. (b) is worse: a second engine has a second `SourceRegistry`, a second `EvidenceStore` and a second repository view, so evidence gathered by a task would not appear in the API's evidence list, and the two could diverge without either being wrong. (c) states the dependency in code, installs it at exactly one place, removes it at exactly one place, and fails with a specific non-retryable error when it is missing. On the completion question: `retryable` exists to distinguish transient from permanent outcomes, and "no source is permitted" is permanent until the owner changes the allowlist. Retrying it burns queue capacity and produces a misleading failure history for an operation that behaved correctly.
- **Consequences:**
  - `app/tasks/handlers.py` holds `RESEARCH_STAGES` (a 6-tuple asserted equal to the `ResearchTaskSpec.stage` `Literal` arguments, so the two cannot drift), `ResearchSweepPayload`, a module-level `_RESEARCH_BACKEND: dict`, `set_research_backend(services)` / `clear_research_backend()`, and `async _research_sweep(payload, ctx)`. `HANDLERS` now has four entries; `research.sweep` is registered `essential=False, retryable=True`.
  - **`ResearchSweepPayload` carries no credentials and no host names.** Egress is decided by the engine and its `NetworkPolicy` at run time, so a payload cannot widen the allowlist — a queued task cannot become a way to reach a host the owner never permitted.
  - `core/application.py` calls `set_research_backend(opportunity_services)` immediately after `initialize_opportunities`, and `clear_research_backend()` in the shutdown `finally` block **before** `services.db.dispose()`, so no handler can touch a disposed database.
  - An unbound backend raises `HandlerError(..., retryable=False)`. Misconfiguration surfaces as a specific, non-retried error rather than an `AttributeError` on `None` or a silently skipped sweep.
  - `essential=False` means the handler is **denied during an owner emergency stop** (ADR-0013), consistently with the other non-essential handlers. Research is not life-support.
  - A sweep reaching no source **completes**, and the refusals it collected are its output. A non-`source_sweep` stage calls `engine.analyse` and returns a `note` stating that it acquires nothing.
  - `ResearchScheduler` remains **caller-timed**: `snapshot()` reports `autonomous_scheduling: False`, and §24 defers scheduling decisions to P-12. `enqueue()` uses idempotency key `f"{opportunity_id}:{stage}"[:128]`, returns a record with a real boolean `dispatched` plus a `reason` when `False`, and **never presents an undispatched task as queued**.
  - `POST /{id}/enqueue-research` is an owner-requested immediate submission. It publishes `ResearchSweepCompleted` only when the task was actually dispatched, and its response states `autonomous_scheduling: false`. It schedules nothing.
  - The binding is a listed owner-ratification item: reaching the engine through an explicit `set_research_backend` rather than implicit application state, failing loudly when unbound.
