# ADR-003 — Windows-First Platform
**Status:** APPROVED (owner lock, 9 Nov 2026) · **Context:** desktop control, local models, filesystem and Windows processes are core needs; future cloud/multi-machine expansion is a stated ambition. · **Options:** (a) Windows-only throughout; (b) cross-platform from day one; (c) Windows-first desktop with expansion-ready architecture. · **Decision:** (c). First production target is Windows desktop (Tauri shell, WebView2, Windows APIs confined to the desktop-control module). The Python/FastAPI core carries no Windows dependencies outside that module, and existing owner assets (ClipOS stack, Fit Life Bro web app) are interfaced, not rewritten (Constitution §14.1 Preservation Rule). · **Reasons:** (a) orphans working assets and the future-expansion clause; (b) spends Horizon 1 effort on platforms with no user. · **Consequences:** P-00 environment audit must verify the Windows toolchain (Rust/MSVC/WebView2) on the target machine; remote monitoring and additional machines arrive at P-12/P-13 without a core rebuild.
