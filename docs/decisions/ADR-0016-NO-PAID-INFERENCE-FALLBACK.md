# ADR-0016: No automatic paid inference fallback; local-first, report the limitation

- **Decision ID:** ADR-0016
- **Status:** Implemented for P-02
- **Context:** ADR-0001 fixes the product as hybrid with a local default and optional cloud. P-02 §6.4 requires *controlled* fallback and states the rule directly: if no permitted model is available, report the limitation instead of silently switching to a paid provider. The host used for P-02 has no inference runtime installed at all, which makes this the normal path rather than an edge case.
- **Problem:** A fallback chain that reaches for a paid API when local inference fails is convenient and invisible. It converts a capacity problem into an unbudgeted financial transaction, and it does so at exactly the moment nobody is watching — the request that failed. With $50 of starting capital and a protected reserve, an unnoticed per-token charge is a real loss, not a rounding error.
- **Options considered:** (a) fall back to any available provider, preferring local; (b) fall back to cloud only when a cost ceiling is configured; (c) exclude unpermitted providers during *selection* so no fallback path can reach them, and return an explicit limitation when nothing permitted is available; (d) queue the request and wait for a local model to become available.
- **Selected decision:** (c). `ModelRouter` filters candidates against `InferencePolicy` **before** attempting generation: cloud models are removed from the candidate list when `cloud_enabled` is false, when the cost ceiling excludes them, or when the request carries sensitive data and `cloud_data_egress_permitted` is false. Because the exclusion happens at selection, there is no ordered fallback list in which a paid provider sits behind a local one — the paid provider is never a candidate at all. When the permitted set is empty the router raises `ModelUnavailableError` carrying the list of models actually tried, and the engine surfaces that as `ResponseStatus.UNAVAILABLE` with a plain-language limitation.
- **Reasons:** (a) and (b) both make spending a side effect of a failure, and (b) still spends without a per-request authorization. (d) turns a capacity problem into a hung request, which §18 forbids: inference must not freeze the Core OS. (c) makes the guarantee structural — the property does not depend on the fallback order being correct, because there is no order to get wrong.
- **Consequences:**
  - With no runtime installed, `"What is AUTONOMUS?"` returns `status=unavailable` and the limitation *"No local inference runtime is installed, and cloud inference is disabled or unauthorized. Paid fallback is never automatic."* It does **not** return a plausible-sounding answer (§20 Scenarios A and E).
  - The guarantee is tested, not asserted: `test_model_router.py::test_no_automatic_paid_fallback` asserts the exact list of models tried is `["local-small"]`, so a future change that appended a cloud attempt would fail the test rather than silently spend money.
  - Local inference is accounted at cost `0.0`. `model_usage` records per-attempt token counts and estimated cost, and is operational accounting only — it is never summed into business revenue or expenses (§17).
  - `inference_max_cost_per_1k_tokens` defaults to `0.0`, which no paid model can satisfy. Raising it is a configuration change the owner makes deliberately; it does not by itself enable cloud routing, which additionally requires the `cloud_ai_enabled` phase flag (see ADR-0015).
  - Sensitive data never reaches a cloud provider without explicit egress permission, independent of cost policy. The two checks are separate so that relaxing one cannot relax the other.
  - The engine degrades to deterministic behaviour: classification, constraint extraction, planning, dependency resolution, scoring and state transitions are all performed by code and continue to work with zero models installed. Only genuinely semantic work is reported unavailable. See ADR-0017.
