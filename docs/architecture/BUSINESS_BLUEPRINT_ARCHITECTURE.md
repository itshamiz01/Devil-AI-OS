# Business Blueprint Architecture (P-06 §8)

A blueprint is the structured plan from which a business is created. It
is generated **deterministically** by `app/business/blueprint.py` from
stored data only: the P-03 opportunity report, the P-03 commercial
analysis, the pinned template definition, and owner-governed settings.
There is no LLM in this environment; generated text is templating over
stored data and is labelled with a generated-notice in every document.
Generated content is **never** independent evidence (§22) — the
blueprint itself is registered as business evidence of type
`internal_generation` with reliability `low` and an explicit limitation.

## The sixteen sections (§8.2)

`executive_summary`, `business_purpose`, `customer_problem`,
`target_customer`, `proposed_solution`, `products_services`,
`value_proposition`, `revenue_model`, `pricing` (a §9 financial value),
`distribution_strategy`, `acquisition_strategy` (plans/drafts only),
`operational_plan`, `technology_requirements`, `content_requirements`,
`brand_identity` (including the name check), `financial_inputs`,
plus `risks`, `constraints`, `assumptions_ref`, `success_criteria_ref`
and `launch_requirements` references.

## Identity and name checking (§8.1)

The name check is automated similarity screening over the portfolio. It
records `conflicts_found` and carries the standing note: **this is not
a trademark clearance and does not establish that a name is legally
available.** No document generated by P-06 claims legal availability,
registration, licensing or certification (§13.3).

## Assumption register (§8.5)

Every blueprint generation also writes assumption rows with: the
assumption, category, basis, status (`VERIFIED` / `SUPPORTED` /
`TENTATIVE` / `UNVERIFIED` / `CONTRADICTED`), impact if wrong,
validation method, and owner. Assumptions are never presented as facts:
serialisations keep their status attached, and readiness dimension A
relies on P-03's computed validation level, not on assumptions.

## Approval (§8)

Blueprints are versioned per business. `approve_blueprint` is an
owner-only, hash-bound P-01 approval over (business, blueprint id,
version): if the blueprint is regenerated, the old approval no longer
verifies (drift fails closed — the same property P-04/P-05 rely on).

## Redaction

All rendered documents pass through a redaction pass
(`blueprint.redact`) that replaces secret-shaped strings (API keys,
tokens, `key=value` secret assignments, bearer tokens) that may exist
in source data. Security test 7 scans every generated file for a
planted secret.
